# Shri Gurukul Academy New Lepa

Fresh Next.js / TypeScript website build inspired by the supplied Sant Siyaram International School screenshots. This is a separate identity for Shri Gurukul Academy New Lepa: original crest artwork, original illustrative school images, responsive pages, an admin CMS, a database-backed enquiry flow, and Cloudinary media uploads.

## Stack

- Next.js App Router and React
- TypeScript, semantic HTML, custom responsive CSS
- Reusable local outline SVG icon system (`components/icon.tsx`) with semantic icons for public pages, navigation, contact methods, and CMS actions
- MongoDB for content, media metadata, and enquiries
- Cloudinary for uploaded image storage and optimized delivery
- `jose` signed admin sessions, `bcryptjs` password hashes, Zod request validation
- Optional Resend notification email (database remains the canonical enquiry record)

## Quick start

Requires Node.js 22.x. The development script runs Next.js with Node.js 22, even if another Node.js version is the system default.

```bash
npm ci
cp .env.example .env.local
```

Set the environment variables described below. Then run:

```bash
npm run dev
```

Visit `http://localhost:3000`. Without a configured MongoDB connection, the site renders editable sample defaults, but submissions, CMS saves, media library uploads, and stored enquiry management will not work until their respective services are configured. This is intentional; the website does not fake successful persistence.

## Configure the admin login

The initial admin email provided for the project is `aventracreative@gmail.com`. Set it as `ADMIN_EMAIL` in `.env.local`.

Generate a password hash. Use a unique password of at least 12 characters and do not commit the password or hash to version control:

```bash
npm run hash-password -- "replace-with-a-unique-password-of-12-or-more-characters"
```

Copy the script’s **escaped** `ADMIN_PASSWORD_HASH=...` line into `.env.local` exactly as printed. Next.js expands `$` references in dotenv files, so an unescaped bcrypt hash can be silently corrupted. For Vercel/hosting provider environment-variable settings, enter the raw 60-character hash without backslashes. Set `AUTH_SECRET` to a cryptographically random value of at least 32 characters. For example: `node -e "console.log(require('crypto').randomBytes(48).toString('base64url'))"`. Never reuse a production secret across projects.

Open `/admin/login` to sign in. There is no public signup or password-reset route. If the initial administrator leaves, update `ADMIN_EMAIL` and `ADMIN_PASSWORD_HASH` through the deployment's secret configuration and rotate `AUTH_SECRET` when appropriate.

### Live Google Sheets enquiry sync

The app saves submissions to MongoDB first, then appends contact enquiries to the `Contact Enquiries` worksheet and admission enquiries to the `Admission Enquiries` worksheet in the configured Google spreadsheet. Submission timestamps are stored and displayed in India Standard Time (IST). The app creates either worksheet if it does not exist and initializes its header row. Google Sheets uses `RAW` values so user-submitted text is not interpreted as spreadsheet formulas. If the spreadsheet is unavailable or not configured, the enquiry remains in MongoDB and the admin Enquiries tab shows it as not synced with a retry action.

To connect a sheet:
1. Enable the Google Sheets API in a Google Cloud project and create a service account.
2. Create or choose a Google spreadsheet, then share it with the service-account email as an Editor.
3. Add `GOOGLE_SERVICE_ACCOUNT_EMAIL`, `GOOGLE_PRIVATE_KEY`, and `GOOGLE_SHEET_ID` to `.env.local` and your production hosting secrets. The sheet ID is the value between `/d/` and `/edit` in its URL. Keep the private key server-only; if entering it as an environment variable, preserve PEM newlines or use `\n` escapes.
4. Optionally set `GOOGLE_CONTACT_SHEET_TAB` and `GOOGLE_ADMISSION_SHEET_TAB` to custom worksheet names. The app creates these tabs automatically on the first form sync. Restart/redeploy, then submit one contact and one admission enquiry to verify that they appear on separate tabs.

## CMS workflow

The admin dashboard includes Overview, a page-by-page editor index, the advanced full-site editor, Media Library, Reel Covers, Enquiries, and Content History. For routine editing, open **Separate page editors** or visit `/admin/pages`; each public page has its own route and focused form.

- **Page-by-page editors:** `/admin/pages` lists individual editors for Home, About, Academics, Admissions, Facilities, School Life, Gallery, Vision & Values, Notices, Calendar, Contact, Disclosure, Privacy Policy, and Site Settings. Each route has page-specific fields and repeatable section controls. Edits remain a draft until **Save changes** is selected. Saves are scoped to the current page or settings group so unrelated page edits are preserved. The **Advanced full-site editor** remains available for technical administrators who need to work with full-content JSON and backups.
- **Media Library:** Uploads raster images to Cloudinary (JPG/JPEG, PNG, WebP or AVIF up to 8 MB), stores metadata in MongoDB, and displays secure image URLs for copying into the content JSON. A media item can only be deleted from Cloudinary after the CMS confirms that its URL/public ID is not referenced by current saved content or one of the retained content-history revisions. Uploading does not silently overwrite site content; review the URL placement and save content explicitly.
- **Reel Covers:** Create and download a 1080×1920 PNG cover. Default backgrounds use bundled local artwork. Cross-origin uploaded backgrounds require Cloudinary to permit canvas export; a CORS restriction is surfaced rather than silently creating a broken file.
- **Enquiries:** Public contact/admission forms validate on both client and server, pass a honeypot field, apply per-process rate limiting, store records in MongoDB and optionally notify the inbox via Resend. Administrators can change enquiry status.

## Media note

The bundled school images are generated illustrative visuals, not photographs of Shri Gurukul Academy. Their source has been cropped into separate optimized WebP assets. The gallery and relevant pages display this disclosure. Replace every illustrative image with approved official academy photography before public launch. The SVG crest is custom vector artwork featuring the school shield and the requested motto “सा विद्या या विमुक्तये”. Confirm the artwork against the academy’s approved emblem before public use.

## Production checklist

1. Set a real HTTPS `NEXT_PUBLIC_SITE_URL`; verify `metadataBase`, sitemap and social previews.
2. Create MongoDB Atlas credentials with a least-privilege database user and restrict network access. Keep backups and test recovery.
3. Configure Cloudinary upload settings, file-size/format policies and account access. Review uploaded image permissions and retention.
4. Set a random `AUTH_SECRET`, `ADMIN_EMAIL`, and bcrypt `ADMIN_PASSWORD_HASH`. Do not use public signup. Enable HTTPS, secure production cookies and rotate credentials if compromised.
5. Put rate limits at the CDN/edge or a shared store in front of the app. The included API rate limiter is in-process and resets on restart; it is not a substitute for distributed rate limiting for a multi-instance deployment.
6. Add a verified Resend sender if email notification is required. Test both the database record and the mail delivery independently.
7. Replace illustrative images and confirm every school fact, staff profile, class, fee, date, facility and disclosure with the school. The current build deliberately makes no CBSE/board/recognition claim.
8. Run `npm run typecheck`, `npm run lint`, `npm test`, and `npm run build` in a network-enabled environment. Fix all errors, test mobile, keyboard navigation, form workflows, CMS save/load, media upload, logout, authorization, and deploy previews before release.
9. Review the starter privacy notice with the school and legal adviser against actual collection, retention, access and email-provider practices.

## Security notes

- Admin sessions are signed and expire after 8 hours; the cookie is HttpOnly, SameSite Strict, and Secure in production.
- Admin API routes require the valid admin session and same-origin mutations.
- Passwords are verified against a bcrypt hash; no password is stored in MongoDB.
- Form and CMS payloads are bounded/validated; uploaded image format and size are checked server-side.
- Security headers include CSP, anti-framing, no-sniff, referrer policy, permissions policy and production HSTS.
- Logs avoid storing enquiry message contents in routine route failure logs.

This is a production-oriented starting implementation, not a certification. Do not represent it as deployed, security-audited, or fully tested until the production checklist has been executed against real configured services.

## CMS image editing and content recovery

Image fields support selecting from Cloudinary media or uploading and attaching a new image. Structured content editors support adding, removing and reordering hero slides, leadership profiles, cards, page sections, FAQs, notices, steps, levels, documents, navigation and footer links. The last 25 prior saved versions are retained in MongoDB and may be loaded into the editor as drafts. The editor marks unsaved changes and warns on attempted browser/tab exit. Media deletion checks both current content and retained revisions. Uploaded files must pass the image signature check and be no larger than 8 MB.

For the visual CMS workflow, media handling, revision history, and a publishing checklist, see [CMS-GUIDE.md](./CMS-GUIDE.md).
